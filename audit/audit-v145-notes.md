# リアル化ラウンド第5弾（v145）棚卸し・修正・見送り記録

実施：2026-11-27。本人の指示「まだがんばれ」（第5弾）。観点は「状態のつながり・読み込みと空状態の作法」。
開始前に git pull で最新化済み（v144 が最新）。カメラは復活させていない。

## 実測で一致していた項目（変更なし）

- **バッジと実体**：プロ未読=2 のセーブで、ホームのグリッド／ドック、カカオ下部タブ、一覧のメイン行バッジが全て「2」で一致（v104／v106 で単一の情報源 kkUnreadTotal に寄せた形が維持されている）。解剖メモ／彼視点／後日談の件数バッジもアプリ内の件数表示と一致。
- **IGのいいね・保存・フォロー**：フィードで付けたいいねが、いいね一覧シート（件数・先頭表示）・「この投稿について」・プロフィール詳細（同一レンダラ igPostHTML）と一致。保存は保存済みタブに即反映、コメントいいね（S.igCmLikes）もシート開閉で保持。フォロー解除時のフォロワー数 −1 も維持。
- **ギャラリーのお気に入り**：ビューア⇔グリッドの ♥ バッジは同一の galFav／S.galFav が情報源で一致。
- **同じ対象の時刻表示**：IG投稿はフィード／詳細／アクティビティ／「この投稿について」が igAgoDisp の単一算出で一致。ニュースは一覧の日付と記事の入力日時（nwInput）が同じ a.date から導出され一致。

## 直した不整合

1. **ニュースのコメントいいねが記事を開き直すと消える**：従来は DOM だけのトグルで、再表示すると件数も状態も初期値に戻っていた（実測：9→10→再表示で9）。単一の情報源として新規セーブ項目 `S.nwLikes`（"記事ID:連番" の配列、既定値は S リテラル＋Object.assign 方式で旧セーブ互換）を新設し、描画・クリックの双方を寄せた。実測：旧形式セーブ（nwLikes 無し）でも 9→10 が再表示・リロード後も保持され、解除も正しく戻る。
2. **IGプロフィールの「フォロー中 86」が両アカウント同一のハードコード**：prof オブジェクト側に ing を持たせ単一化（ジェオン 74／なお 86）。フォロワー数の算出式と同じ場所で管理する形にした。
3. **空状態の作法がバラバラ**：1行テキストだけ（IG検索0件、カカオ検索0件、通話履歴0件）、地の文 <p>（写真ピッカー0件）、locknote のみ（ギャラリー0枚時）などを、共通形 `.es-box`（アイコン＋見出し＋補足）に統一。対象：IG検索／IGコメント／写真ピッカー／ギャラリー（全削除時を含む）／通話履歴／カカオ検索／IGアクティビティ／IG保存済み。ニュース検索の既存形（見出し＋補足）が基準。
- なおコメント0件は到達可能な全状態（calU 0〜11 × 全投稿）を実測し、常時コメントが存在するため防御的な分岐であることを確認した上で、スタブ投稿で描画分岐自体を検証した。
4. **画像の読み込み作法の残り**：v144 で IG 投稿写真だけに入っていたフェードイン（imgFade）を IG グリッド／ギャラリー／写真ピッカーのグリッドへ拡張。地色プレースホルダをニュースサムネイル（.nw-th）、アバター類（img.av ほか）、ストーリー画像に追加。寸法は全て従来どおり固定で、読み込みで跳ねる箇所は無かった。追加したフェードは prefers-reduced-motion で無効化される側に含めた。

## 検証結果

Playwright 実駆動（iPhone 390×844・タッチ）で検証し全 PASS、JS エラーゼロ。
- 新規／旧形式（nwLikes 無し）／進行中（calU=11）の各セーブで実施。ニュースいいねの保持（再表示・リロード・解除）、空状態8か所の表示、全9アプリ到達、本編のタップ進行（プロローグ→選択肢→第1章の吹き出し出現まで）を確認。
- 本編の台詞・数値・解放条件・LSKEY・写真割り当ては不変。新規セーブ項目は nwLikes のみ（既定値方式＋防御的初期化で旧セーブ互換）。

## 見送った候補と理由

- **解剖メモのフッタ件数（MEMOS 総数）とバッジ（収集中件数）**：測っているものが違う（目録総数／収集数）表示で、アプリ内の作法として一貫しているため変更なし。
- **いいね一覧シート内の空表示（cm-empty）**：シート内の一覧行としての文脈で、全面の空状態とは作法が異なるため共通形の対象外とした。
- **カカオショッピングのカート**：バッジ表示は無く、商品シートとカートは S.kkCart の単一管理で一致していたため変更なし。
