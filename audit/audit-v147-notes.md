## 直した破綻（3件）

1. **#タブ検索の入力だけ 14.5px で iOS 自動ズーム**（実害）
   - カカオ # タブの検索入力 `#ksh-q`（`.ksh-search input`）だけ font-size 14.5px で、実機フォーカス時に iOS Safari の自動ズーム閾値（16px）を割っていた。他の実テキスト入力は全て 16px（実測: free-in / cm-in / igs-in / nt-q / nw-q / チャット検索 / プロフィール編集ほか）。
   - → 16px に統一。あわせて v72 ブロックの「実テキスト入力は #free-in のみ」という陳腐化したコメントを現状に更新。
2. **フォロー中リストの件数がプロフィールと食い違い**（v145 の単一化漏れ）
   - `openFollowList` のシート見出しが `'86'` 固定で、ジェオンのプロフィール表示「フォロー中 74」と開いたシートの「フォロー中 86」が食い違っていた（なお側は 86 で偶然一致）。
   - → `prof.ing` に単一化。実測: ジェオン=74 / なお=86 でプロフィールと一致。
3. **ホームをスクロールするとステータスバーが読めなくなる**
   - ホームは全面スクロール（.home-scroll）のため、白いウィジェットや明るいアイコンが浮いたステータスバー（白文字）の下に潜ると時刻・電波表示が読めなかった（スクショで確認）。
   - → #v-home の上端にステータスバー帯のすりガラス（暗色 rgba(9,11,19,.42) + backdrop-filter blur 16px）と、その下端に 26px の薄い影（::after）を追加。スクロール中も帯の上では常に読める。他ビューはヘッダーが不透明で同種の問題なし。ロック画面は全面が暗色で視認性を保つため対象外。

## 実測で問題なかった項目

- **幅違いの崩れ**: アニメーションを止めた精密実測で、360/390/430/短高660 の全ビューに横はみ出し・テキスト切り捨てなし。唯一のはみ出しは v-call の着信背景画像（cover 配置の意図的なブリード、画面でクリップされる）。
- **最長データ**: 本編の台詞は短文主義で吹き出しは max-width 252px + break-word のため溢れなし（実フローで45タップ進行して実測）。IG のいいね数はデータ上最大 1,876 件・フォロワー最大 2,088 と桁が小さく、試験的に「いいね！1,234,567件」「12,345,678」を注入しても行・スタッツとも溢れなし。
- **スクロール到達性**: 主要スクローラ全て最下部まで到達可能で、最終要素がドック/タブバー/入力バーに隠れない（ホームは padding-bottom 118px > ドック占有 97px）。
- **セーフエリア**: --sat/--sab に実インセット（47px/34px）を注入して実測。ステータスバー高・カカオタブバー・チャット入力・フリー入力・IGナビ・コメントバーの下余白が全て追随。ホーム先頭余白も max(56px, sat+12) で追随。
- **キーボード相当のリサイズ**: ビューポート高 844→500→844 で電話枠（--ph）が追随し、フリーチャット入力行は常に画面下端に密着（キーボードで枠が縮む v79 の経路を再確認）。
- **モーション軽減**: 陽性対照（RMなしで kvDrift / flutLock×3 の無限アニメを検出）つきで監査。prefers-reduced-motion 時はロック/ホーム/ストーリー（プログレスバーは scaleX(1) 静止）とも稼働中アニメーション 0 件。v144 の Ken Burns・光の明滅・蝶、v146 のカスケード・シマー含め漏れなし。
- **スクロール端の背景**: 主要スクローラは全て overscroll-behavior: contain で、背後のビュー背景（単色/テーマ色）の上に乗るため、端で色が切れたり素地が覗いたりしない。
- **シート類の画面内収まり**: コメントシート / 商品シート（高さ370px）/ ギャラリービューア / サイドトークを実フローで開いて画面内に収まることを実測。

## 見送った候補と理由

- **横向き（740×360）**: 電話枠が 378×162 に縮むのはホストページ側の「縦向き電話枠」という見せ方の帰結で、本作の対象（縦持ち実機）ではないため現状維持。横はみ出しの主因も閉じたチャットドロワー（オフキャンバス）で破綻ではない。
- **チャットドロワーの overscroll-behavior**: ドロワー内リストは白背景のパネルで、端の見え方に問題がないため contain の追加は見送り（他の主要スクローラは付与済み）。
- **ロック画面のステータスバー帯**: 全面が暗色キービジュアルで、スクロールしても白文字の視認性が保たれるため、ホームと同じ帯は入れない。
