# v153 監査ノート ― 動きの質ラウンド（ui-animation の型＋GSAP の型）

対象スキル：ui-animation（新規導入）／gsap-core・gsap-timeline（型のみ）。計測はローカル配信＋ Playwright（Python、iPhone 390×844・タッチ）で実駆動し、transform／opacity の時系列サンプリングで裏付けた。本編・台詞・数値・解放条件・LSKEY・セーブ形式・写真割り当ては不変。新規セーブ項目なし。カメラは復活させていない。

## GSAP ライブラリの組み込み判断：見送り（型のみ採用）

- 本作は単一 HTML＋素の CSS/JS でビルド工程がなく、必要な動きは全て CSS transition／keyframes と WAAPI で足りる。GSAP 本体（約70KB〜）を足すと v151 で −55% にした転送量削減と正面衝突し、得られる能力（タイムライン合成・物理バネ）に対して見合わない。
- 採用した型：①入退場の非対称（入場は ease-out 系、退場は accelerate 系で短く）②中断可能性は「現在の実値から次の動きを始める」（GSAP の overwrite／live value の考え方を WAAPI で実装）③着地直前の減速（close の tail）を嫌い、出口カーブは Material の accelerate を基準にする。

## 直した項目

### 1. シート／ドロワーを閉じる時の「出だしの重さ＋終盤の鞭打ち」
- 原因：閉じカーブ `cubic-bezier(.55,0,.85,.4)` は序盤がほぼ水平で、実測では全体の 10% を進むのに 139ms かかり、残り半分を最後の約46ms で鞭のように消化していた（ui-animation の型でいう close の tail／lag-then-whip）。
- 修正：閉じ側 7 箇所（静的 CSS 6＋実行時注入の mk-sheet 1）を Material accelerate `cubic-bezier(.4,0,1,1)` に統一。開き側のバネ（.52s／.44s）は実測で健全（オーバーシュート −3px）なため不変。旧カーブの残置なし。

### 2. トーストの入退場の非対称化
- 原因：入退場とも `.35s ease` で、入場 t90=242ms と間延びし、退場も消え始めが鈍かった。
- 修正：退場（素の状態）＝ `.18s ease-in`、入場（`.on` 状態側で宣言しシートと同じ作法）＝ `.25s cubic-bezier(.22,1,.36,1)`。v152 の「transition は opacity/transform を明示」ルールは維持。`toast()` のタイマーリセット（v47）は不変で、二重アニメーションは無し（実測で単一遷移を確認）。

### 3. 画面遷移の中断可能性（再入場の点滅／退場開始時の跳ね）
- 原因：v146 の入退場は CSS キーフレーム固定で、①退場途中の画面へ戻ると入場（vin）が opacity 0 から再起動して一瞬消える、②入場途中の画面を閉じると退場キーフレームの `from{opacity:1}` に跳ねてから消える、の2つが実測で再現した。
- 修正：showView ラッパーで退場・再入場を **実値（computed opacity／translateX）から WAAPI で駆動**する形に置き換え。あわせて判明した重要点：**スクリプト生成アニメーション（WAAPI）は CSS キーフレームより合成優先度が低い**ため、bye／vin の CSS アニメーションを `getAnimations()` で cancel してから WAAPI を載せている（cancel しなければ WAAPI が負けることを実測で確認）。WAAPI が使えない環境では従来の CSS キーフレームがそのままフォールバックになる（WAAPI 生成に成功した時だけ CSS を cancel）。v146 の方向設計（前進 byeF／後退 byeB、z-index 優先度、ロック画面除外、back フラグ）は不変。reduced-motion 時は従来どおり退場アニメーション自体を付けない。

### 4. カレンダーの入場アニメーション再発火
- 原因：v146 のカスケード（一度だけ入場）は8種のリストに効いていたが、カレンダー（`.cal-grid`／`.cal-pager`／`.cal-e`）だけ対象外で、`renderCal()` が月送りのたびに innerHTML を作り直すため fadeup が毎回再生されていた。姉妹作品の同ラウンドで取れた「行ごとの入り方の不揃い」と同型。
- 修正：上書き側（animation:none 群）とカスケード側の両セレクタに3クラスを追加し、`renderCal()` から `__casc(b,'cal',…)` を呼ぶ（初回だけカスケード、以降は無音）。ドットタップの予定フラッシュ（calflash）がカスケード側に負けないよう `.cal-e.flash` の詳細度を引き上げ（実測：初回表示でも calflash が再生）。reduced-motion の `animation:none!important` が引き続き最優先。

### 5. ＋パネルに閉じる動きが無かった
- 原因：開く時は vin（横方向 14px の汎用入場を流用）で、閉じる時は即 display:none のハードカットだった。パネルは下部固定なので横移動も不自然。
- 修正：専用キーフレーム ppIn（translateY 12px→0＋フェード、.2s）／ppOut（フェード＋translateY 8px、.13s、accelerate）を新設し、開閉を `togglePP()`／`closePP()` に集約（両方の＋ボタン `#btn-plus`／`#btn-plus2` の 'on' 同期もここで一元化）。閉じアニメーション中に再度開いた場合は `.bye` 残存チェックでタイマーが開いた状態を消さない（実測：高速 開→閉→開 で開状態を維持）。旧 vin 流用ルールは削除。reduced-motion 時は従来どおり即時クローズ。カレンダージャンプ等、他所からの即時 `remove('on')` は大きな画面遷移に隠れるため対象外（現状維持）。

## 検討して見送った候補

- **シートの開きバネ**：オーバーシュート実測 −3px（v146 計測と一致）で、ui-animation の型でも許容範囲。中断時の反転も滑らか。変更なし。
- **いいね連打時の `.pop` クラス残留**：5連打で最終状態（liked／セーブ値）一致。`.pop` は fill 無しのキーフレームで見た目に残らず、再押下で reflow 経由で再生されるため実害なし。
- **メーター類の遷移（.5s／1.2s ease）**：進捗の意図的な開示であり、操作応答ではないため対象外。
- **通知バナー（#noise）の transition 定義重複**：後勝ちで .55s 両方向に統一されており実害なし。タップでディープリンク遷移するため退場速度の影響も小さい。
- **チャットドロワーの背景（.25s）と本体（.46s）の不一致**：よくある作法の範囲で、実測でも破綻なし。
- **INP 改善の content-visibility 導入**：v152 で見送った判断を維持（v140／v141 の IG スクロール復元と衝突しうる）。
- **GSAP 本体の組み込み**：冒頭の判断のとおり見送り。
